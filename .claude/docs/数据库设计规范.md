# 数据库设计规范

> 详细规范与菜单 SQL 模板见 `.agents/skills/database-ops`。本文是速览。

## 硬性规则

1. 表名/字段名**全大写下划线**；新业务表前缀 = 所在插件：biz 插件用 **`BIZ_`**，自建插件用插件名（snowy-plugin-order → **`ORDER_`**）（出厂 biz 域复用 SYS_/DEV_ 表是历史设计，勿模仿）
2. 主键 `ID varchar(20)` 字符串雪花（MyBatis-Plus ASSIGN_ID），**禁** bigint 自增
3. 每表尾部固定字段组：其中 DELETE_FLAG、CREATE_TIME、CREATE_USER、UPDATE_TIME、UPDATE_USER 五个由 `CommonEntity` 提供（逻辑删除 + 自动填充，代码里不要手动赋值）；SORT_CODE、REMARK、EXT_JSON **不在** CommonEntity 中，Entity 要自己声明 sortCode / remark / extJson（参考 BizNotice）：

```sql
`SORT_CODE` int NULL COMMENT '排序',
`REMARK` varchar(500) NULL COMMENT '备注',
`EXT_JSON` longtext NULL COMMENT '扩展信息',
`DELETE_FLAG` varchar(255) NULL COMMENT '删除标志',
`CREATE_TIME` datetime NULL COMMENT '创建时间',
`CREATE_USER` varchar(20) NULL COMMENT '创建用户',
`UPDATE_TIME` datetime NULL COMMENT '更新时间',
`UPDATE_USER` varchar(20) NULL COMMENT '更新用户',
```

4. 表与字段都要**中文 COMMENT**；utf8mb4 / InnoDB
5. 树形表加 `PARENT_ID varchar(20)`；关联字段 `varchar(20)` 存对方 ID
6. 唯一性：不要用数据库唯一索引（逻辑删除冲突），Service 层查重

## 标准建表模板

```sql
CREATE TABLE `BIZ_SUPPLIER`  (
  `ID` varchar(20) NOT NULL COMMENT '主键',
  `NAME` varchar(100) NULL COMMENT '名称',
  `TYPE` varchar(50) NULL COMMENT '类型（字典 SUPPLIER_TYPE）',
  `STATUS` varchar(10) NULL COMMENT '状态（ENABLE/DISABLE）',
  -- 业务字段……
  `SORT_CODE` int NULL COMMENT '排序',
  `REMARK` varchar(500) NULL COMMENT '备注',
  `EXT_JSON` longtext NULL COMMENT '扩展信息',
  `DELETE_FLAG` varchar(255) NULL COMMENT '删除标志',
  `CREATE_TIME` datetime NULL COMMENT '创建时间',
  `CREATE_USER` varchar(20) NULL COMMENT '创建用户',
  `UPDATE_TIME` datetime NULL COMMENT '更新时间',
  `UPDATE_USER` varchar(20) NULL COMMENT '更新用户',
  PRIMARY KEY (`ID`) USING BTREE
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '供应商' ROW_FORMAT = Dynamic;
```

## 类型映射

| Java | MySQL |
|---|---|
| String（短） | varchar(n) |
| String（长文本） | text / longtext（EXT_JSON 用 longtext） |
| Integer | int |
| BigDecimal | decimal(18,2) |
| Date | datetime（datetime 列一律映射 Date，与 CommonEntity 审计字段、生成器 GenDbTypeUtil 一致） |
| String（按字符串存的纯日期，如存量 BIRTHDAY、ENTRY_DATE） | varchar |
| 加密字段 | varchar 放宽（SM4 密文变长） |

## 菜单/按钮 SQL（SYS_RESOURCE）

权威模板：`snowy-plugin/snowy-plugin-gen/src/main/resources/sqlend/Mysql.sql.btl`。按钮码驼峰式（前端 hasPerm 用）：

```sql
INSERT INTO `SYS_RESOURCE` VALUES ('{menuId}', '{父id}', '供应商管理', 'supplier', '{code}', 'MENU', '{moduleId}', 'MENU', '/biz/supplier', 'biz/supplier/index', '{icon}', NULL, 'YES', 'YES', 'YES', 99, NULL, 'NOT_DELETE', NULL, NULL, NULL, NULL);
INSERT INTO `SYS_RESOURCE` VALUES ('{btnId}', '{menuId}', '新增供应商', NULL, 'bizSupplierAdd', 'BUTTON', NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, 1, NULL, 'NOT_DELETE', NULL, NULL, NULL, NULL);
```

按钮码集合以 sqlend 模板为准：单表/树/主表为 `biz{Xxx}Add/Edit/Delete/Detail/BatchDelete/Import/Export`；左树右表另有 `biz{Xxx}TreeAdd/TreeEdit/TreeDelete/TreeDetail`；主子表另有 `biz{Xxx}SubAdd/SubEdit/SubDelete/SubDetail/SubBatchDelete/SubImport/SubExport`（业务动作另加，如出厂的 bizGroupGrantUser、bizOrgCopy）。

> 代码生成器"项目内生成"时会直接写入菜单和按钮，并给超管授权菜单与接口，不需要再执行 SQL（重复执行会产生重复菜单）；ZIP 方式才需要手动执行 sqlend 产出的 SQL。

## 现有 33 表（前缀分组）

- **SYS_**（12）：SYS_USER、SYS_USER_EXT、SYS_USER_PASSWORD、SYS_USER_DATA_SCOPE、SYS_USER_DATA_SCOPE_MAP（数据范围预计算表）、SYS_ORG、SYS_ORG_EXT、SYS_POSITION、SYS_ROLE、SYS_GROUP、SYS_RESOURCE（模块/目录/菜单/按钮都在这张表，用 CATEGORY 区分）、SYS_RELATION（用户-角色、角色-资源、角色-接口权限、用户-组等各类关系统一存放）
- **BIZ_**（1）：BIZ_NOTICE
- **DEV_**（12）：DEV_CONFIG、DEV_DICT、DEV_EMAIL、DEV_FILE、DEV_JOB、DEV_LOG、DEV_MESSAGE、DEV_PUSH、DEV_RELATION、DEV_SLIDESHOW、DEV_SMS、DEV_WEAK_PASSWORD
- **GEN_**（2）：GEN_BASIC、GEN_CONFIG
- **CLIENT_**（4）：CLIENT_USER、CLIENT_USER_EXT、CLIENT_USER_PASSWORD、CLIENT_RELATION
- **MOBILE_**（1）：MOBILE_RESOURCE
- **AUTH_**（1）：AUTH_THIRD_USER（三方登录用户）

准确清单：`grep "CREATE TABLE" snowy-web-app/src/main/resources/_sql/snowy_mysql.sql`

## SQL 脚本管理

- 全量脚本：`snowy-web-app/src/main/resources/_sql/snowy_mysql.sql`
- 增量 DDL：也放 `_sql/` 下，命名 `{日期}_{功能}.sql`（如 `2026-08-18_supplier.sql`）
- AI 执行 SQL 降级链：mysql CLI → 落盘 `docs/sql-pending/` 提示手动执行
