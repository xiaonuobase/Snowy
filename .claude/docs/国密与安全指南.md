# 国密与安全指南

> Snowy 的定位是"国密前后端分离平台"，提供国密算法能力；能否通过等保或密评，取决于部署方式、密钥管理（出厂密钥必须替换，见 CommonCryptogramUtil 类注释）和测评结论。详细 API 见 `.agents/skills/crypto-sm` 与 `.agents/skills/security-auth`。

## 国密三层架构

| 层 | 算法 | 保护什么 | 实现 |
|---|---|---|---|
| 传输加密 | SM2（非对称） | 登录口令网络传输 | 前端 smCrypto.js 公钥加密 → 后端 CommonCryptogramUtil.doSm2Decrypt |
| 口令摘要 | SM3（哈希） | 口令存储 | CommonCryptogramUtil.doHashValue（SysPasswordUtil 只负责默认密码、复杂度、历史密码与过期校验，没有摘要方法），库中只有摘要 |
| 字段加密 | SM4-CBC（对称） | 手机号/证件号等落库 | CommonSm4CbcTypeHandler（MyBatis TypeHandler） |

当前密钥常量位于 `CommonCryptogramUtil`（私钥与 SM4 密钥经 CommonKeyUtil 做 XOR 混淆存储，生产环境用 CommonKeyUtil 重新生成），前端公钥位于 `smCrypto.js`；没有 `snowy.cryptogram.*` 配置绑定。调整密钥需同步前后端并迁移已有 SM4 密文。

## 敏感字段加密（新字段标准做法）

```java
@TableName(value = "BIZ_PATIENT", autoResultMap = true)      // 1
public class BizPatient extends CommonEntity {

    @TableField(typeHandler = CommonSm4CbcTypeHandler.class)  // 2
    @Schema(description = "手机号")
    private String phone;
}
```

查询限制（重要）：
- 明文不能直接对密文字段做 like 查询；精确查用 `in(字段, CommonCryptogramUtil.doSm4CbcEncryptCandidates(明文))`，同时命中 CBC 新密文和历史 ECB 密文（不要用 eq + doSm4CbcEncrypt，老数据会查不到）。整值 SM3 摘要辅助列只能支持精确匹配/查重，不能支持子串查询。
- 密文格式：当前为 CBC + Base64，老库里的十六进制密文是旧版 ECB 格式，读取和查询自动兼容，记录编辑保存时自然转为新格式，升级无需迁移数据（新格式写入后不能回退到旧版本，升级前建议备份）。详见 `.agents/skills/crypto-sm`。
- 参考实战：BizUser 的 phone/idCardNumber/emergencyPhone

## 口令处理规范

- 传输：SM2（前端加密，后端解密）——新业务口令类字段照抄登录链路
- 存储：SM3 摘要——**任何口令不得明文/可逆存储**
- 日志：不打口令与敏感字段明文。注意平台 `@CommonLog` 不做脱敏，会把整个入参写入 DEV_LOG.PARAM_JSON（出厂 `/sys/user/add`、`/biz/user/add` 就是这样）；新接口入参含敏感字段时要自行处理，不要拿出厂用户接口当范本

## 鉴权安全

1. **白名单最小化**：免登录接口必须逐条登记 GlobalConfigure.NO_LOGIN_PATH_ARR（改后重启）；禁止用通配符放开大范围
2. **越权防护**：编辑/删除接口校验数据归属（当前用户机构/本人）；关键操作加 @CommonNoRepeat
3. **SQL 注入**：QueryWrapper 一律 checkSqlInjection() + lambda 列名；动态排序字段过 CommonSortOrderEnum.validate + toUnderlineCase
4. **上传安全**：走 dev/file 标准接口；图片 / 文档专用接口（`uploadImageDynamicReturnId/Url`、`uploadDocumentDynamicReturnId/Url`）按后缀白名单校验（图片 jpg/jpeg/png/gif/bmp/webp，文档 pdf/doc/docx/xls/xlsx/ppt/pptx/txt，只校验后缀不检查内容）；需登录的下载走 `/dev/file/authDownload`，免登录的 `/dev/file/download` 必须带 sign 签名参数
5. **会话**：Sa-Token 有效期 30 天（`sa-token.timeout`），出厂 `sa-token.is-concurrent=false` 已禁止同账号并发登录（新登录挤掉旧登录）；敏感系统建议缩短有效期

## 权限体系要点（防越权设计）

- 接口权限：@SaCheckPermission 值 = URL，权限 = 用户直接授权 + 所属角色授权的**接口权限**（角色管理 / 用户管理 → **授权权限**，存 SYS_RELATION 的 SYS_USER_HAS_PERMISSION / SYS_ROLE_HAS_PERMISSION）；"授权资源"只控制菜单和按钮，不产生接口权限。**新接口不授权 = 默认拒绝**（默认安全），超管（`superAdmin`）也不例外：手写的新接口必须到 角色管理 → 授权权限 给超管勾选，否则超管也 403（代码生成器项目内生成时会自动给超管授权）
- 按钮权限：驼峰码只控制显示，**后端必须有自己的校验**（前端隐藏不是安全边界）
- 数据范围：平台**没有**数据权限自动拦截器，只用 QueryWrapper 不会按机构过滤。敏感数据列表要在 Service 里显式调用 `StpLoginUserUtil.getLoginUserDataScope()`（null = 全部，空集合 = 无授权机构，非空 = 机构 id 集合，用 `CommonSqlUtil.safeIn` 加条件；参考 BizUserServiceImpl / BizPositionServiceImpl）；范围在 角色管理 / 用户管理 → 授权权限 里按接口配置
